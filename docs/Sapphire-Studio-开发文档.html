📖一、项目概述

Sapphire Studio 是一个 AI 工作站，提供 AI 对话、Tool Calling、联网搜索等功能。底层基于 Next.js 15 App Router、Supabase 数据库、Shadcn UI 组件库。

CMS 后台负责管理用户、微信用户、RBAC 权限和仪表盘数据。/chat 是主要的 AI 交互界面。

1.1 核心定位

模块说明
AI Chat主页面 /chat，SSE 流式对话 + Tool Calling，支持联网搜索、天气查询、数学计算等
CMS 后台/cms/dashboard，用户管理、微信用户管理、RBAC 权限系统
Demo Chat/demo/chat，新版 UI，包含 ToolCallBubble 可视化（调用状态实时展示）
MBTI/mbti，MBTI 人格测试功能

1.2 技术栈总览

类别技术
框架Next.js 15 (App Router)
语言TypeScript
数据库Supabase (PostgreSQL)
UIShadcn UI + Radix UI + Tailwind CSS
状态管理Zustand (vanilla) + React Query

认证自定义 JWT + bcrypt

🔌五、模型接入层

文件：src/lib/ai-client.ts — 这是整个 AI 系统的唯一入口。

import { createOpenAI } from "@ai-sdk/openai";

// 懒加载：模块导入时不立即初始化，避免 DEEPSEEK_API_KEY 缺失时启动崩溃
let _deepseek: ReturnType<typeof createOpenAI> | null = null;

function getDeepSeekClient() {
  if (!_deepseek) {
    const apiKey = process.env.DEEPSEEK_API_KEY;
    if (!apiKey) {
      throw new Error(
        "DEEPSEEK_API_KEY is not set. " +
        "Please add it to your environment variables."
      );
    }
    _deepseek = createOpenAI({
      apiKey,
      baseURL: process.env.DEEPSEEK_BASE_URL || "https://api.deepseek.com/v1",
    });
  }
  return _deepseek;
}

// Proxy 代理：对 deepseek 的所有属性访问都经过懒加载
export const deepseek = new Proxy({}, {
  get(_target, prop) {
    const client = getDeepSeekClient();
    const value = client[prop];
    return typeof value === "function" ? value.bind(client) : value;
  },
});

export const CHAT_MODEL = "deepseek-v4-flash";

5.1 模型选型

模型状态说明
deepseek-v4-flash当前使用默认模型，速度快、成本低，适合流式聊天
deepseek-v4-pro按需升级特定功能需要更强推理时单独切换
deepseek-chat已弃用将于 2026/07/24 弃用，已全部替换
⚠️ 生产环境注意：必须在 Vercel 环境变量中配置 DEEPSEEK_API_KEY。
代码已做懒加载保护——key 缺失时不会在模块加载阶段崩溃，而是在首次调用时抛出清晰的错误信息。

🧰六、AI 工具集

文件：src/services/chatTools.ts — 四个工具全部使用 Vercel AI SDK v7 的 tool() 定义，包含 Zod 输入校验和异步执行函数。全部在服务端执行。

6.1 工具一览

工具名数据源需 Key说明
getWeather wttr.in 免费 免费天气 API，返回 JSON (?format=j1)。8 秒超时。支持全球城市英文名。
getCurrentTime Intl.DateTimeFormat 内置 JavaScript 内置 API。支持时区参数，默认 Asia/Shanghai。
calculate 沙箱化 new Function() 内置 安全的数学表达式求值器。白名单 Math 函数（sin、sqrt、log 等）。无全局作用域访问。
webSearch DuckDuckGo HTML 抓取 免费 抓取 html.duckduckgo.com/html/ 搜索结果页，解析 title/snippet/url。最多 8 条结果，10 秒超时。

6.2 工具定义示例

import { tool } from "ai";
import { z } from "zod";

export const getWeather = tool({
  description: "查询指定城市当前天气。返回温度、天气状况、湿度、风速等信息。",
  inputSchema: z.object({
    city: z.string().describe("城市名称，使用英文如 Beijing, Shanghai"),
  }),
  execute: async (input) => {
    const url = `https://wttr.in/${encodeURIComponent(input.city)}?format=j1`;
    const res = await fetch(url, { signal: AbortSignal.timeout(8000) });
    const data = await res.json();
    const current = data.current_condition?.[0];
    return {
      temperature: `${current.temp_C}°C`,
      condition: current.weatherDesc?.[0]?.value ?? "未知",
      humidity: `${current.humidity}%`,
    };
  },
});

// 所有工具统一导出，传给 streamText()
export const chatTools = {
  webSearch,
  getWeather,
  getCurrentTime,
  calculate,
} as const;

🤖七、Agent 系统

文件：src/config/agents.ts — Agent 是纯配置对象，通过不同的 system prompt 和工具开关来定制 AI 行为。

7.1 Agent 配置接口

interface AgentConfig {
  id: string;              // 唯一标识
  name: string;            // 显示名称
  description: string;     // 描述
  icon: string;            // Lucide 图标名: "Bot" | "Search"
  systemPrompt: string;    // 发送给模型的 system prompt
  model: string;           // 默认 "deepseek-v4-flash"
  temperature: number;     // 默认 0.7
  maxTokens: number;       // 默认 2000
  enableWebSearch: boolean; // 是否在 prompt 中强调联网搜索
}

7.2 当前 Agent

ID名称核心行为
default 默认助手 通用 AI 助手，日常对话和问题解答。不强调联网搜索。
search 联网搜索 主动联网搜索——遇到时间敏感问题（天气、新闻、攻略等）时先调 webSearch 再回答。要求注明来源链接。

7.3 添加新 Agent

  1. 在 agents 数组中新增一条配置
  2. 新 Agent 自动出现在 Chat 侧栏的 Agent 选择器中（无需改 UI）
  3. 如需自定义图标，在 chat-sidebar.tsx 中添加图标映射
💡 设计意图：Agent 只是"角色扮演"——同一个模型、同一套工具，但 system prompt 不同导致行为差异。
未来如果需要不同模型、不同工具集、甚至不同 provider，可以扩展这个接口。

🌊八、流式数据流

一条用户消息从输入到存储的完整旅程：

┌──────────────────────────────────────────────────────────────┐ │ Browser │ │ chat-store.ts.sendMessage() │ │ ├─ Creates conversation (if new) │ │ ├─ Adds user message optimistically │ │ ├─ POST /api/chat (SSE request) │ │ │ ↓ │ │ │ Server: chatService.streamChatResponse() │ │ │ ├─ Save user message to Supabase │ │ │ ├─ toModelMessages() — 转为 AI SDK 格式 │ │ │ ├─ streamText({ model, system, messages, tools }) │ │ │ ├─ 遍历 fullStream → SSE 事件: │ │ │ │ "text-delta" → { type: "text", content } │ │ │ │ "tool-call" → { type: "tool-call", ... } │ │ │ │ "tool-result" → { type: "tool-result", ... } │ │ │ │ "finish" → { type: "done" } │ │ │ ↓ │ │ │ Client: 读取 SSE 流 │ │ │ ├─ text: 增量拼接到 assistant message │ │ │ ├─ tool-call: 追加到 toolCallRecords[] │ │ │ ├─ tool-result: 更新对应的 toolCallRecord │ │ │ └─ done: 标记 isStreaming=false │ │ │ │ │ │ Post-stream（服务端，非阻塞）: │ │ │ ├─ 保存 assistant message 到 Supabase │ │ │ ├─ 更新 conversation.updated_at（Supabase） │ │ │ └─ 检查是否需要摘要（≥20 条消息） │ │ └─────────────────────────────────────────────────────────┘ │ Client: loadConversations() 刷新对话列表顺序 │ └──────────────────────────────────────────────────────────────┘

8.1 SSE 事件类型

定义在 src/types/chat/index.ts 的 ChatStreamEvent：

事件方向载荷
textServer → Client{ type: "text", content: string }
tool-callServer → Client{ type: "tool-call", toolCallId, toolName, args }
tool-resultServer → Client{ type: "tool-result", toolCallId, toolName, result }
tool-errorServer → Client{ type: "tool-error", toolCallId, toolName, error }
doneServer → Client{ type: "done", finishReason }
error双向{ type: "error", error: string }

8.2 关键设计决策

  • 消息持久化在服务端：用户消息在流开始前保存，助手消息在流结束后保存。客户端断开也不丢消息。
  • Tool 调用上限：stopWhen: isStepCount(5) 限制最多 5 轮 tool call，防止无限循环。
  • 摘要触发阈值：对话超过 20 条消息时，自动用前半段历史生成中文摘要，存入 conversation_summaries 表。
  • Side effects 非阻塞：时间戳更新、摘要生成都是 fire-and-forget，不阻塞 SSE 流。

🗄️九、状态管理

Chat 状态使用 Zustand vanilla store（非 React Zustand），通过 React Context 注入。

9.1 Store 结构

字段/方法说明
conversations对话列表（从 API 加载）
currentConversationId当前选中对话 ID
currentMessages当前对话的消息列表（从 API 加载）
currentAgentId当前选中的 Agent（默认 "default"）
isLoading加载状态
sendMessage(content)发送消息 → SSE 消费 → 更新 state
loadMessages(conversationId)从 API 加载消息（替代旧 localStorage）
loadConversations()加载对话列表
createConversation(title?)创建新对话
deleteConversation(id)删除对话（消息由 DB 级联删除）

9.2 消息存储

消息全部存在 Supabase messages 表，不再使用 localStorage。dev 和 prod 共用同一数据库时对话自动同步。

表存储内容
conversations对话元数据：id、user_id、title、model、agent_id、时间戳
messages消息：id、conversation_id、role、content、tool_calls (JSONB)、created_at
conversation_summaries摘要：id、conversation_id、summary_text、message_count

🔐十、认证系统

  • JWT Token：自定义签发/验证（src/lib/jwt.ts），Cookie 存储（HttpOnly + SameSite=Strict）
  • 密码哈希：bcrypt，强度 10
  • 路由保护：中间件保护 /dashboard 路由；Chat API 路由使用 requireAuth()
  • 账号要求：用户必须 isActive: true，且 user_type 为 admin 或 user
🔒 安全提醒：服务端始终使用 supabase-admin（绕过 RLS）操作数据库。
SUPABASE_SERVICE_ROLE_KEY 仅用于服务端，绝不暴露到客户端。
