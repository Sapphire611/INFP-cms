🏗️ 架构决策

1. 不动现有 users 表

user_type（admin/user）已满足 B2C 模型。积分、分析结果单独建表，零迁移风险。

2. 微信用户保持独立

wechat_users 已有 mbti 字段，Phase 2 仅添加可选的 user_id 外键做身份关联。

3. 测评题目落库 + 服务端计分

mbti_questions 表种子数据写入 48 题（每维度 12 题），服务端算法计算类型，客户端不参与计分逻辑。

4. AI 分析复用 DeepSeek

沿用 chatService 的 openai SDK 调用模式，替换为 MBTI 专用 system prompt + 结构化输出，零新依赖。

5. 积分原子性

消费积分时用 UPDATE … WHERE balance >= amount 做乐观锁，影响 0 行则拒绝，防并发超扣。

🧮 计分算法

服务端 /api/mbti/sessions/[id]/complete

// 1. 取出该会话所有答案
// 2. 按维度 (EI / SN / TF / JP) 分组
// 3. 每维度统计 A 数量 vs B 数量
// 4. 多数方决定字母:
//    EI: A≥B → E, 否则 → I
//    SN: A≥B → S, 否则 → N
//    TF: A≥B → T, 否则 → F
//    JP: A≥B → J, 否则 → P
// 5. 组装 4 字母类型 (如 INFP)
// 6. 平局默认取首字母 (偏 E/S/T/J 侧)
